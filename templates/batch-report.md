# batch-report 模板 v0.2（七组字段，缺一不计入统计）

> **引用格式强制**：所有 file:line 必须写"完整文件名:行号"（如 `src/agent/loop.py:42`）；省略文件名将导致机械对账低估（试点实测）。
> 用法：每个子代理/batch 一份。字段与设计书 §6.2 契约 1 对应；对账器按字段核对齐全性。
> 判定证据级别：断言级（读码）/ 执行级（跑测试或脚本）/ 复现级（构造触发用例）。
> FAIL 判定必附"独立核验路径"；PASS 必附"反证记录"。

## 批信息

- batch_id：｜ 任务集：tasks.jsonl 中 task_id 列表 ｜ 快照（commit）：
- 执行者（模型与版本）：｜ 时间：｜ token 用量：

## 判定记录（每条一行块）

### [判定 N]

1. **file:line（原始仓库）**：
2. **代码摘录（完整逻辑单元：整函数/整块）**：
   ```text
   （摘录）
   ```
3. **判定**：PASS / FAIL / N/A（JUDGMENT-NA 必附撤销条件）
4. **严重度**：critical / high / medium / low（对照 severity-anchors.json；安全类对齐 CVSS 档）
5. **反证记录（PASS 必填；FAIL 豁免）**：已检索且未命中的反例模式列表
6. **证据级别**：断言级 / 执行级 / 复现级（FAIL 至少执行级才可定 Critical/High，否则降级标注）
7. **独立核验路径（FAIL 必填）**：第三方如何机械复现该 FAIL（命令/输入/预期输出）
8. **解析性溯源**：判定 ↔ 任务 id（实验映射列：experiment_id↔checkpoint_ids，无实验填 "—"）
9. **判定稳定率（可选）**：同任务双跑结果是否一致（一致/不一致/未双跑）

## 批级汇总

- 判定计数：PASS ／ FAIL ／ N/A ／ 悬置（RUNTIME-UNVERIFIED / DEFERRED / SKIP-HUMAN，逐项注明重试条件）
- 悬置清单（一次性体检：列出重试条件即可，不建状态机）
- 备注（模型自述的困难、可疑处——供审计环节参考，不替代证据）

## 盲判记录（抽验用）

- 盲判者（模型）：｜ 盲判时间：｜ 是否已看原判定：否（先盲判）/ 是（后对答案）
- 盲判结论与原判定的一致情况：一致 / 不一致（不一致逐项列出）
