# 审查员操作规程（reviewer-brief · C 档纪律单源）

> 本文件是派发提示词的唯一纪律来源：派发词只说「本批特有事项＋指路本文件」，不再逐次复述纪律。
> 与骨架/词表的关系：判定词表与报告结构由 `generate_tasks --report-skeletons` 的骨架文件给出（代码单源）；本文件只管**裁量纪律**。

## 1. 只读与边界（允许清单——白名单之外的动作一律不做）

允许的动作**只有三类**：①Read/grep 读仓内工作树文件；②把文件**复制到** runtime-lab/experiments/<task_id>/ 后在副本外运行并留 log（intent＋脚本＋log 三件套）；③写自己的报告文件。除此之外——改仓内文件、在仓内执行其脚本（会落 __pycache__）、git 历史命令（log/blame/show/diff）——都不在允许清单里。

## 2. 证据契约

1. 五元组：file:line ＋ 整块摘录（原样≥1 行）＋ 判定 ＋ 严重度 ＋ 反证记录。**未命中也要反证记录**（"若有 X 应在 Y 出现，实测 grep 0 命中"）。
2. 引用格式（强制）：完整相对路径:行号（如 `scripts/audit.py:26`）——省目录名会被 fields --repo 判引用失效。
3. 证据级别三态必标：断言级（读码）／执行级（跑过）／复现级（构造触发用例）。
4. 报告自述不算证据：仓内任何 .md 的宣称必须回代码核验后才可采信。
5. **经济条款**：粗筛/阴性判定每检查点一两句＋证据即可，命中项才展开——把笔墨花在阳性上。
6. 判级先对照 `data/severity-anchors.json` 的同型例（12 例冻结锚——凭语感判级是 G5 要防的漂移源）。

## 3. 判定口径

1. 判定词表：命中／未命中（反证）／N/A／JUDGMENT-NA（池任务用 pool_result：阴性／阳性／混合）——与报告骨架里的枚举一致，勿造新词。
2. **口径立规**：阳性仅当检查点缺陷主体在仓内被真实实例化；类比命中／字面命中（文档同名词、确定性等价物）只写「邻域观察」。
3. N/A 双轨：机械可核验（引底册证据）或 JUDGMENT-NA（须附撤销条件）。
4. 诚实降级：跑不了的标 RUNTIME-UNVERIFIED；悬置必须带重试条件。禁止冒充 PASS。

## 4. 红线

1. D-004 密钥纪律：真实密钥值不入任何文件（只写位置＋脱敏指纹，如 `sk-****abcd`）。
2. 发现池判错了要如实翻案（这是"池化翻案率"的度量输入），并修正行号/计数。
3. 报告写进骨架文件（batch-reports/<task_id>.md），sidecar 同名 .json 填 verdict/severity/citations（citation 可带 excerpt 字段——fields 会拿它对照实文件行核验摘录真实性）。sidecar 空着也不报错（校验器回退扫 md），但填了才能启用摘录核验并免词表误判。

## 5. 返回格式

每任务一行：`task_id｜判定｜严重度｜一句话`；另有「翻案清单」。不复述报告全文。
