# 原子化过程：检查点如何变成可验收的任务

> 本文说明本技能的核心工序——把"审查一个项目"从一句大话，变成一批**单一对象、单一动作、可机械验收**的原子任务。这是全套设计的脊柱：检查点池回答"查什么"，原子化回答"怎么查、查到什么程度算数"。

## 为什么要原子化：粒度反转律

防偷懒不是一个态度问题，是一个**成本结构**问题。

- 任务粗（"审查这个项目的循环控制"）时：伪造便宜——写一段流畅的"已审查，未发现问题"几乎零成本，而真做要读遍全库。此时只能靠过程管理（打卡、台账、抽查）去盯。
- 任务细到"单一检查对象 × 单一判定动作"（"枚举 `src/agent/loop.py` 全部 async 函数，逐一列出是否存在未 await 的返回，附摘录"）时：**真做比伪造便宜**——真做是读数、复制、标注；伪造要编出文件名、行号、摘录，还要在复核时对得上。撒谎的代价超过了照做的代价。

于是，**管理被前置到任务设计里**：运行期不再需要过程纪律，只需要一个"收集+对账"的循环。粒度越细，运行期越自由。

（这条定律的精确表述是"粒度 × 廉价机械验证"的乘积——细分只是把伪造的证据面切小，对账与抽验才能击穿它。两者缺一都会退化成口号。）

## 四步工序

### 第 1 步　前置解剖（enumerate.py）

先不问代码"有没有问题"，只问"有什么"。八个枚举器把项目摊平成一份 JSONL 底册：

| 子命令 | 产出 |
|---|---|
| files | 全文件 + 行数 + hash + 变更热区（churn） |
| entry | 入口点（main / 路由 / 框架初始化） |
| env | 环境变量引用 + `.env.example` 键 |
| tools | 工具/schema 注册点 |
| prompts | prompt 文件与内嵌模板串 |
| deps | 依赖清单与版本锁定状态 |
| intent | 意图基线（README / 测试断言 / 类型签名） |
| sinks | 危险汇聚点（exec/eval/pickle/subprocess/文件写…） |

这份底册是**任务挂载点的宇宙**——后续每条任务必须挂在它的某个具体行上，覆盖断言也以它为准。

### 第 2 步　任务原料 = 池 × 底册 × 意图

- **池**（`data/`）给"查什么"：每条检查点是一次判定请求；
- **底册**给"在哪查"：文件、行号、符号名；
- **意图基线**给"对照什么判偏差"：缺陷是代码与意图的偏差，没有意图就只能查坏味道。

三者相乘（配合严重度与变更热区加权），生成候选任务集。

### 第 3 步　AMR 循环：粗查一遍，热处加密

任务集不是一次性摊开的清单，而是一个**由粗到细的加密循环**（借鉴数值计算的"自适应网格加密"）：

1. **粗网格**：每层生成一个**池化筛查任务**——一个任务覆盖全文件集的同类判定。阴性一次排除一片，阳性下钻细查。
2. **加密**：对 critical/high 检查点 × **变更热区文件**（churn 排序）生成**下钻任务**，逐条给出五元组证据。
3. **停机**：额度耗尽或（后续版本）最大未检覆盖率低于阈值。

两级原子对应两种采样：**池化 = 低通采样**（一次抓系统性面），**细粒度 = 全带采样**（逐点判）。这等价于群组测试的核心思想——缺陷稀疏时，池化能把查询数从 O(n) 压到 O(d·log(n/d))。

### 第 4 步　原子任务规格

每条任务的形状固定为三层：

- ❌ 反例："审查 L5 循环控制。"（对象模糊、动作模糊、无法验收）
- ✅ 正例："枚举 `src/agent/loop.py` 全部 async 函数，逐一列函数名/行号/是否存在未 await 返回，附摘录。"（单一对象、单一动作、输出格式明确）

产出 `tasks.jsonl`（机器读：task_id / tier / layer / checkpoint_ids / targets / 快照 / expected_format）＋ `atomic-tasks.md`（人读任务表）。

## 验收：完成由对账定义

- **覆盖断言**：每个 `active` 检查点必须挂到 ≥1 个任务；每个底册文件必须被 ≥1 个任务覆盖。覆盖率为 0 → 自动 FAIL（`audit.py coverage / reconcile`）。
- **快照绑定**：任务绑定 commit 快照；仓库漂移则受影响任务作废重排。
- **对账不平不许收尾**：任务必须有产出、产出必须带证据五元组（file:line＋摘录＋判定＋严重度＋反证记录）。

## 为什么这是一份"快照"而不是一份"清单"

- 同一套原子化引擎可以喂任何池（`--data` 换档：全量/快速/安全/LLM/agentic…）——任务随池而变。
- 任务集随项目快照而变——旧任务集对旧 commit 有效，不假装永恒。
- 池里的检查点可增删（带来源标注与版本号）——原子化引擎不改一行。
